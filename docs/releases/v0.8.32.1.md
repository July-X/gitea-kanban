# v0.8.32.1 — GitHub 仓库刷新 `remote: invalid credentials` 修复（Bearer → Basic）

> 发布日期：2026-07-31
> commit：（待 push 后回填）
> tag：（待打）
> release：https://github.com/July-X/gitea-kanban/releases/tag/v0.8.32.1

## 问题背景

v0.8.32 上线后，Windows 用户切到 GitHub 私有仓库点「刷新」，`commits.gitgraphPull` 报：

```
remote: invalid credentials
fatal: Authentication failed for 'https://github.com/July-X/gitea-kanban.git/'
```

实际调用链：

```
TimelineNewView.goToLatest
  → commitsGitgraphPull({ projectId })
  → app.PullRepoByProjectId
  → git.PullRepo(UseGitHubCLI=true)
  → app/git/sync.go: FetchWithFilter
  → app/git/native.go: fetchRemoteWithFilter
  → gitbinary.RunGitWithEnv(GIT_CONFIG_*=Authorization: Bearer <token>)
```

## 根因

**v0.8.32 错把 GitHub REST API 的 `Authorization: Bearer <pat>` 用到了 Git Smart HTTP 协议上**：

- GitHub REST API（`/repos/...`、`/user`）鉴权用 `Authorization: Bearer <token>` ✓
- Git Smart HTTP（git fetch 走 `git-receive-pack` / `git-upload-pack` over HTTPS）鉴权用 **Basic credential**，username 固定为 `x-access-token`，password 是 PAT 原文

v0.8.32 调研时把 GitHub 鉴权方式"凭印象"写成 Bearer，没区分 REST API 和 Smart HTTP 两个协议层的鉴权差异。Smoke test 只验证了公开仓库 `ls-remote`（不传 token），没覆盖私有仓库带 token fetch——bug 没在 v0.8.32 验证阶段暴露。

## 改动内容

### 1. `app/git/native.go` 鉴权构造从 Bearer 改 Basic

抽纯函数 `buildGitHubFetchAuthEnv(token string) map[string]string`：

```go
// v0.8.32.1 正确做法
cred := base64.StdEncoding.EncodeToString([]byte("x-access-token:" + token))
env["GIT_CONFIG_VALUE_0"] = "Authorization: Basic " + cred
```

行为：
- `strings.TrimSpace(token)`：用户从 Gitea/GitHub Web 复制 PAT 时偶尔会带换行 / 空格，不 trim 会让 base64 编码失败
- token 空白 → 返空 map，不注入任何 `GIT_CONFIG_*`（公开仓库 fetch 无需鉴权）
- 限定 url 到 `http.https://github.com.extraHeader`（不是全局 `http.extraHeader`）→ token 不会泄露给其它 gitea remote host

### 2. `app/git/native.go` 401 / 鉴权失败识别 → `IpcError(github_auth_failed)`

加 `isGitHubAuthFailure(err error) bool` 关键字识别：

| 关键字 | 来源 |
|---|---|
| `remote: invalid credentials` | GitHub Smart HTTP 401 标准输出 |
| `Authentication failed for` | git transport 包裹后的通用 401 文案 |
| `fatal: authentication failed` | 旧版 git 表述 |

匹配时 `fetchRemoteWithFilter` 返回 `ipc.NewGitHubAuthFailed(truncateForHint(err.Error()))` 而不是把 git 内部输出原样抛给用户。`truncateForHint` 截断到 200 字符，避免暴露完整 env / 命令行 / 堆栈。

### 3. `app/ipc/errors.go` 加 `NewGitHubAuthFailed` 构造函数

新错误码 `github_auth_failed`（v0.8.32.1）：

- message：`GitHub 凭证无效，或当前账号没有读取该仓库的权限`
- hint：`请重新连接 GitHub 账号；私有仓库 token 需要读取权限，组织仓库可能还需要完成 SSO 授权`
- cause：截断到 200 字符的 git 输出（不包含 token / base64 header / env）

### 4. 前端 `KNOWN_ERROR_CODES` / `CODE_CATEGORY` / `RECOVERABLE` 三处扩展

`frontend/src/lib/ipc-client.ts` + `frontend/src/shared/errors.ts` 加 `github_auth_failed` 支持：

- KNOWN_ERROR_CODES 白名单加 `'github_auth_failed'`
- CODE_CATEGORY 类别前缀 `账号权限`
- RECOVERABLE=true（重连 GitHub 账号可恢复）

### 5. 测试覆盖

`app/git/native_test.go` 重写 `TestFetchRemoteWithFilter_EnvHasExtraHeader`：

- 断言 `Authorization: Basic ` 前缀（不再是 Bearer）
- base64 解码验证内容为 `x-access-token:<token>`
- 反向断言 `Authorization: Bearer ` 不再出现（防 v0.8.32.1 退化）

新增 4 个测试：

- `TestFetchRemoteWithFilter_EnvTokenTrimmed`：token 前后空白 trim
- `TestFetchRemoteWithFilter_EnvOnlyWhitespaceToken`：全空白 token 当空
- `TestIsGitHubAuthFailure`：6 个子用例覆盖 3 个关键字 + 2 个无关错误 + nil
- `TestNewGitHubAuthFailed`：验证 code/message/hint/cause + 防止 token / base64 泄露到 message/hint

`TestGitEnvFor_ExtraEnvOverrides` 的测试 fixture 同步从 Bearer 改 Basic(x-access-token:fake) 保持一致。

**测试 helper 简化**：删 `buildFetchEnvForTest` 测试 helper（之前是复制生产逻辑的"镜像"），直接测生产代码的 `buildGitHubFetchAuthEnv`，避免测试和实现再次漂移。

### 6. 测试统计

- v0.8.32：70 测试 / 11 包
- v0.8.32.1：75 测试 / 11 包（+5 测试 / +0 文件）

## 回归风险

| 风险 | 缓解 |
|---|---|
| Base64 编码后 token 仍可能在错误日志暴露 | `NewGitHubAuthFailed` 的 cause 截断到 200 字符；前端 message/hint 也不包含 `ghp_` 前缀或 `Authorization: Basic ` 字串（`TestNewGitHubAuthFailed` 防泄露断言） |
| 用户 trim 后误以为 token 失效 | trim 是 silent 的（base64 编码能容忍）；`TestFetchRemoteWithFilter_EnvTokenTrimmed` 锁住行为 |
| Gitea 私有仓库走错分支 | `http.https://github.com.extraHeader` URL scoped config 限定到 github.com 域（已有，不动） |
| 用户 PAT 真的过期 / 权限不足 / 组织未 SSO 授权 | 改 Basic 后仍 401 → `isGitHubAuthFailure` 识别 → 返回 `github_auth_failed` 引导重连，而不是只看到 "应用出错了" |
| v0.8.32 文档里 `Authorization: Bearer` 描述需更新 | AGENTS.md §10 第 12 条改 Bearer→Basic + v0.8.32 release note 已补"v0.8.32.1 修订" 段 |

## 不决事项（不在本版本范围）

1. GitHub Organization 强制 SSO 场景的 OAuth Device Flow 引导（v0.8.32 路线规划）
2. 其他私有 git host（Gitea enterprise / GitLab）走 Git Smart HTTP Basic 的兼容（如果未来用户反馈再加）
3. PAT 自动 refresh（OAuth token 才有 refresh，PAT 没有，只能让用户重连）
