# v0.8.23.4 — Windows 自动更新 Win32 740 UAC 提权修复

> 发布日期：2026-07-29
> commit：`8840906`（fix）+ `6d15af8`（docs）
> tag：`v0.8.23.4` → `e7328a16`
> release：https://github.com/July-X/gitea-kanban/releases/tag/v0.8.23.4

## 问题背景

User 截图反馈：v0.8.23.3 安装版点"检查更新"→ 检测到 v0.8.23.4 新版本 → 下载 → 进入 apply 阶段 → 失败并提示"可手动重试"。

错误信息：

```
update:apply failed: launch NSIS installer, fork/exec ...gitea-kanban-v0.8.23.3-windows-amd64-installer.exe: The requested operation requires elevation.
```

错误码 **Win32 740 ERROR_ELEVATION_REQUIRED**。

### 根因

`app/updater/updater_windows.go:91`（v0.8.23.3 之前）的 applyWindows 走 `exec.Command(installerPath).Start()`，底层调 `CreateProcess`。

NSIS installer 的 manifest 声明 `requireAdministrator`（要写 `C:\Program Files\`），但 `CreateProcess` **不会触发 UAC**——直接返 740 让旧逻辑失败。

正确方式必须是 **`ShellExecuteExW` + `lpVerb="runas"`**——这是 Windows 唯一能弹 UAC 的 API。

## 改动内容

### 1. applyWindows 改走 ShellExecuteExW + runas 触发 UAC

**文件**：`app/updater/updater_windows.go`

完整重写 applyWindows 路径：

- 新增 `shellExecuteInfoW` 结构体：Win32 `SHELLEXECUTEINFOW` 的 Go 镜像，**字段顺序/类型严格按 Win32 头文件**，cbSize 用 `unsafe.Sizeof` 算（避免将来加字段忘改）
- 新增 `launchElevated(installerPath, shortInstallDir)`：调 `ShellExecuteExW`，`fMask = SEE_MASK_NOCLOSEPROCESS | SEE_MASK_FLAG_NO_UI`，`lpVerb="runas"`，`nShow=SW_HIDE`，`lpParameters="/S /D=<短路径>"`
- 沿用 `getShortPathNameW`（v0.8.16 引入）解决 NSIS `/D=` 不支持引号且遇空格截断的问题
- 成功后 `os.Exit(0)` 退出旧进程，让 NSIS 覆盖文件

### 2. 失败路径 + UAC 取消语义

**文件**：`app/updater/updater_windows.go`

- **UAC 用户点"否"**（Win32 errno=1223 ERROR_CANCELLED）→ 静默返回 nil，不算 bug，仅日志记录
- **其他 ShellExecuteExW 失败**（errno=2/3/5/11/26/27/31 + 未知）→ fallback 到 `explorer.exe /select,<installerPath>` 打开下载目录，让用户手动双击；同时返 `ErrApplyFailed` 包装错误，前端 IPC 提示"可手动双击运行安装包"
- `win32ErrorHint(errno)` 把常见 errno 翻成人话（找不到文件 / 路径不存在 / 访问拒绝 / 安装包损坏…）

### 3. launchElevatedWith 可注入版本 + 6 个单测

**文件**：`app/updater/updater_windows_test.go`

- `launcherForTest` 函数类型让测试注入 fake launcher，捕获 `SHELLEXECUTEINFO` 入参
- `TestShellExecuteInfo_CbSize`：cbSize = unsafe.Sizeof(struct)，结构体尺寸 sanity 检查
- `TestLaunchElevated_PassesRunAsVerb`：验证 `lpVerb="runas"` / `lpFile=installerPath` / `lpParameters="/S /D=<短路径>"` / `nShow=SW_HIDE` / `fMask` 包含 `SEE_MASK_NOCLOSEPROCESS` 和 `SEE_MASK_FLAG_NO_UI`
- `TestLaunchElevated_UACCanceled`：UAC 取消 → `errors.Is(err, errElevationCancelled)`
- `TestLaunchElevated_OtherFailure`：非 1223 错误透传
- `TestWin32ErrorHint`：5 种 errno → "人话"翻译
- 保留 v0.8.0.1 的 `TestGetShortPathNameW_Basic` + `TestInstallerCommandLine_ShortDir`

## 影响范围

- 仅 Windows 自动更新 apply 阶段
- macOS / Linux / dev build / Wails binding / 前端 / DTO / CI workflow 全部不动
- 失败 fallback（explorer.exe）保留用户可手动重试路径，避免出现"升级彻底走不通"的死路

## 向后兼容

- v0.8.0 引入的 `getShortPathNameW` + `installerCommandLine` 全部保留，`installerCommandLine` 现仅供日志/调试输出
- 旧的 `exec.Command` 路径彻底删除，不再依赖
- v0.8.16 修的 NSIS `/D=` 空格问题在 ShellExecuteExW 路径下同样有效

## 不动 / 不要做

- 不要把安装目录切到 `%LOCALAPPDATA%` 走 per-user 安装（那是产品决策，需要单独的 #design 评审）
- 不要用 task scheduler / RunAs 服务等其他提权机制，保持 ShellExecuteExW 单 API
- 不要在 v0.8.23.4 加 macOS 自动更新路径改动（v0.8.23.1 已稳定，本次只修 Windows）
