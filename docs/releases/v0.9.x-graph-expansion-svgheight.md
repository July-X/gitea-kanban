# v0.9.x patch — GitGraph 展开 commit-row 后 Graph 错位 patch 2（兜底 svgHeight 自算）

> 紧接 v0.9.x 上一个 patch（vscode-render 加 expandedHeight 参数）后，**用户实测仍看到 Graph 错位**——本轮加强制兜底。

## 真因（深挖发现）

v0.9.x 上一个 patch 让 `renderGraphVscode` 接 `expandedHeight` 参数，但高度字段计算里仍有 fallback：

```ts
// vscode-render.ts:209-211
const expandY =
    options?.expandedHeight && options.expandedHeight > (options.expandY ?? VSCODE_EXPAND_Y)
    ? options.expandedHeight                                    // 优先级 1：实际高度
    : (options?.expandY ?? VSCODE_EXPAND_Y);                   // fallback：250
```

调用链：
- **TimelineNewView 传** `expandedHeight: expandedHeight.value || undefined` + `expandY: activeExpandY.value || undefined`
- **`activeExpandY`** = `expandedHeight.value > 0 ? max(250, expandedHeight.value) : 0`
- 所以 accordion mount **瞬间**（ResizeObserver 还没异步 fire）`expandedHeight.value === 0` → `activeExpandY === 0` → `options.expandY === undefined`
- `renderGraphVscode` 三元运算：`undefined && ... ? undefined : (undefined ?? 250)` → 走 fallback **250**

**r.height 输出的"展开后高度"按 250 算**，但 DOM commit-row 总高度按 accordion 真实高度（~350-450px）。

即使 ResizeObserver 之后异步补到 350，`svgRender` 是 computed 是响应式的，按理应该重算——但**响应式更新依赖 Vue 调度 + resize observer callback 触发**，期间若 DOM 已经渲染了（首帧 + 状态过渡帧），SVG height 短暂就是 250。用户看到的是 React 异步性带来的**持续错位**（尤其切换 commit 触发多次 ResizeObserver fire 时）。

## 修复方案（兜底）

**让 `svgHeight` 完全自算，不依赖 `r.height`**：

```ts
// TimelineNewView.vue:1532 (新)
const svgHeight = computed(() => {
  const dto = graphDto.value;
  if (!dto) return '0px';
  const nodeCount = dto.nodes.length;
  const gridY = dynamicGridY.value;
  const offsetY = dynamicOffsetY.value;
  const basePx = nodeCount * gridY + offsetY - gridY / 2;
  return `${basePx + expandedHeight.value}px`;
});
```

**关键差异**：

| 维度 | 旧（依赖 r.height） | 新（自算） |
|---|---|---|
| 数据源 | `renderGraphVscode` 返回值的 `height` 字段 | `graphDto.nodes.length` + `dynamicGridY.value` + `expandedHeight.value` |
| 算式 fallback | vscode-render 内部 `expandY ?? 250` 仍会触发 | **完全不走 fallback**——`expandedHeight.value` 是 ref，`0` 时 height 缩成无展开态 |
| 稳定性 | 依赖 vscode-render 内部算式正确 | 与 vscode-render 解耦——同步引用 DOM 测量与 graphDto |
| 副作用 | 无 | 极轻微：accordion 内容比 graphDto 多 0~2px 时（极少见），SVG 边缘会略下垂；不影响 dot 位置 |

## 用户视角验证

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 展开第 1 行（短 commit + 短 files） | 即使算正确 height 也偶尔下方 commits 看到 dot 缺失（rAF + ResizeObserver 异步） | **SVG 永远撑满**——下方 commit 立即可见 dot/line |
| 展开中间行（多 bullet + 多 files） | 错位最严重 | 与 DOM commit-row 严丝合缝 |
| 快速切换展开行 | ResizeObserver 多次 fire，svgRender 重算有延迟，期间 SVG 高度用旧值 | 直接读最新 `expandedHeight.value`，跟着 DOM 走 |

## 与 v0.9.x 上一个 patch 关系

上一个 patch（fab58818）让 `vscode-render.ts` 接 `expandedHeight` 参数——这部分对其它调用 svgHeight vscode-render 的代码有用（自动算 height 字段），**保留**。本轮只改 `svgHeight` 计算源头，不动 vscode-render 内部 height 字段。
