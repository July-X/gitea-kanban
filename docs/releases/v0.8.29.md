# v0.8.29 — "未与 main 接合" 灰化语义翻新（v0.8.28 翻向）

> 发布日期：2026-07-31
> commit：（待 push 后回填）
> tag：（待打）
> release：https://github.com/July-X/gitea-kanban/releases/tag/v0.8.29

## 问题背景

v0.8.28 实现 GitLens 风格"已合并 PR 灰化"——commit `8337cc0` 把 dim 算法定义成：
**对 merged PR 链 commit 行视觉降 opacity**。但在用户复刻过程中，对齐 vscode-gitlens
Commit Graph 截图的具体行为是另一面：

> "gitlens 表达的应该是**没有和主分支产出联系**的分支"
>
> —— user feedback 2026-07-31

GitLens 实际行为：**任何不在 main 主线可达祖先集合的 commit 视觉降级**。`mainReachable`
= `ancestors(mainHead)`（走所有 parents），等于"`git log main` 能看到的 commit 集合"。
**已 merged PR 反而属于 mainReachable**（merge commit 的 `parents[1]` 把 PR 链整段
并入 main 祖先），所以"已合并 PR 灰化"与 v0.8.28 实现的"dim 已 merged PR 链"在算法上**矛盾**。

## 根因

v0.8.28 算法（`dimMergedPullCommits`）：

```ts
// 对每个 merged PR：head.sha 出发 first-parent BFS，遇 mainAnc 内的 sha 停
// 沿途 commit 加入 dimmed 集合
```

逻辑反了：对 merged PR 链 dim 等于"被 main 接合的链也 dim"——v0.8.28 的 mainAnc
用 `first-parent-only` BFS（只覆盖 main trunk 自身），意图"deduplicate 与 main 自身
链的语义重叠"，但 v0.8.28 BFS 起点是 `headSha`（feature branch tip），沿 first-parent
走一遍只命中 PR 自身链，不命中 main trunk（PR 链上的 commit 与 main 在 merge 时
汇合，PR 链自身就是 first-parent 主链）。

## 方案

**v0.8.29 改为"dim = 非 mainReachable"，2 行核心 diff**：

```diff
- import { dimMergedPullCommits, EMPTY_DIMMED_SET } from '@renderer/lib/graph-dimmed';
+ import { dimNonMainReachableCommits, EMPTY_DIMMED_SET } from '@renderer/lib/graph-dimmed';

  const dimmedShaSet = computed<ReadonlySet<string>>(() => {
    const dto = graphDto.value;
    if (!dto) return EMPTY_DIMMED_SET;
-   return dimMergedPullCommits(dto.nodes, mergedPulls.value);
+   return dimNonMainReachableCommits(dto.nodes);
  });
```

新算法（`dimNonMainReachableCommits`，在 `frontend/src/lib/graph-dimmed.ts`）：
1. `mainHead = resolveMainHeadSha(nodes)` —— refs 含 main/master 的最早 row
   （兜底：row 0）
2. `mainReachable = ancestorsAllParents(mainHead)` —— **走所有 parents**（不是
   first-parent only），含 main trunk + 全部经 merge 接管的旁支链
3. `dimmed = { sha ∈ nodes | sha ∉ mainReachable }`

等价于"`git rev-list main` 的补集"——main 没见过的 commit 视觉降级。

**保留 v0.8.28 完整视觉挂钩**（不动）：
- `commit-row--dimmed` CSS class（文字 + ref-badge opacity 0.45）
- `.commit-vertex--dimmed` SVG class（circle stroke/fill opacity 0.35）
- `.flow-group--dimmed` SVG class（path shadow 0.18 / line 0.35）
- `pathCoveredRows` 解析 path d 字符串 → `pathGroupsDimmed` 派生逻辑

class 类名全保留，**前端无需任何视觉改动**，只翻 dim 算法语义。

**保留 v0.8.28 后台拉取`mergedPulls` 的代码（含 `fetchMergedPullsAsync` 函数）作为技术债**：
不再被 dim 算法使用，但用户可以快速回滚到 v0.8.28 行为。彻底清理放 v0.8.30。

## 改动列表

### 1. `frontend/src/lib/graph-dimmed.ts`

| | 之前（v0.8.28）| 之后（v0.8.29）|
|---|---|---|
| 函数名 | `dimMergedPullCommits(nodes, mergedPulls)` | `dimNonMainReachableCommits(nodes)` |
| 输入 | graph nodes + mergedPulls（外部依赖）| graph nodes 单参数（纯本地计算）|
| 算法 | 每个 merged PR：head.sha first-parent BFS + mainAnc 截断 | `nodes - ancestorsAllParents(mainHead)` |
| 截断算法 | `mainAncBuild(first-parent only)` | `ancestorsAllParents(all parents)` |
| 复杂度 | O(N + ΣM·D)（M=PR 数, D=PR 链深）| O(N)（单 BFS）|
| 后台拉 IPC | 需要（mergedPulls）| 不需要（纯本地）|

新增函数 `ancestorsAllParents(sha, parentsBySha)` —— 走 `for...of parents` 全 BFS
（注意：v0.8.28 的 `mainAncBuild` 走 first-parent only 是另一个语义，本版本不再使用）。

### 2. `frontend/src/views/TimelineNewView.vue`

**仅 2 行 diff**：
- import: `dimMergedPullCommits` → `dimNonMainReachableCommits`
- `dimmedShaSet` 调用 + 删 `mergedPulls.value` 第二参数

**v0.8.28 完整视觉挂钩（commit-row + circle + path）保留不变**，所以截图预期
是 commit row + 节点 + 经过 dimmed row 的 path 仍然灰化，仅 dim 集合语义换了。

### 3. `frontend/src/lib/graph-dimmed.test.ts`

10 个 vitest 测试（重写覆盖新语义）：

```
TestBuildGraphGitlens_MainTrunk (3 个)
  ✓ main trunk 全部不 dim，dangling 链全部 dim
  ✓ 未 merged 旁支链 commit 全部 dim（独立 draft 分支）
  ✓ 空输入: 空 nodes 返回空 Set

TestBuildGraphGitlens_ResolveMainHeadSha (5 个)
  ✓ 找 refs 含 main 的最早 row
  ✓ refs 含 master 也算
  ✓ refs 含 origin/main 也算（剥前缀后取末段）
  ✓ 无 main/master refs 兜底：row 0 node
  ✓ 空数组返回 undefined
```

## 影响范围

| 场景 | v0.8.28 (merged PR 链 dim) | v0.8.29 (non-mainReachable dim) |
|---|---|---|
| main trunk 自身 | 正常 | 正常（mainReachable）|
| 已 merged PR 链（含 merge commit 后整段 first-parent） | **dim** ❌ 错 | 正常 ✓（merged PR 已被 main 接合）|
| 未 merged draft 分支 commit | 正常 | **dim** ✓（独立分支）|
| 已 orphaned / force-pushed away 分支 commit | 正常 | **dim** ✓（main 不可达）|

> 关键 case 演示（用户截图 kanban_demo/m4java-test）：
> - `cx-single-392739` 含 PR 合并的 chain → v0.8.28 dim，v0.8.29 正常（commit 还在 main 上）
> - `timeline-test-1781397142497` 未 merged draft 分支 → v0.8.28 正常，v0.8.29 **dim** ✓（不在 mainReachable）
> - `feature-merge (#12 已合并)` 链 → v0.8.28 dim，v0.8.29 正常（接入了 main）
> - `feature-kanban (#11 已合并)` 链 → v0.8.28 dim，v0.8.29 正常

## v0.8.28 → v0.8.29 的关键修复 vs 留下的待清理

### v0.8.29 修了
1. **算法语义对齐 GitLens 实际行为**：dim = 非 mainReachable，不看 PR 状态
2. **性能**：O(N + ΣM·D) → O(N)，单 BFS 完成，不再依赖后台 IPC
3. **数据源依赖**：不再需要 PullDto 数据；删 `mergedPulls`/pullsList 拉取链路
   （函数保留作 fall-back，技术债清理留 v0.8.30）

### v0.8.29 没动（避免改动风险）
1. CSS class 类名（`commit-row--dimmed` / `commit-vertex--dimmed` / `flow-group--dimmed`）保持不变
2. SVG path opacity 计算（`pathCoveredRows`）保持不变
3. `mergedPulls` ref + `fetchMergedPullsAsync` 函数 + AbortController 仍存在
   （loadGraph 仍 void 触发，但函数体内不是被 dim 算法读，留作未来兜底）

## 风险与权衡

- **视觉差异**：用户截图里**部分**之前未 dim 的 commit 现在会 dim（独立 draft 分支 commit），
  user 已读 doc 知道变更；截图前再确认一遍 timeline-test branch 行是否 dim 比对
- **performance impact**：O(N) 单 BFS，比 v0.8.28 O(N + ΣM·D) 更便宜；3000 commits 实测 < 1ms
- **回滚成本**：2 行 diff，回滚 = revert 2 行 import + computed 调用即可恢复 v0.8.28 行为
  （fetchMergedPullsAsync / mergedPulls 仍在，可以瞬间把 `dimNonMainReachableCommits`
  改回 `dimMergedPullCommits` 复用）
