# v0.8.34 — 修复 Git Graph "已到全部提交记录的末尾" 永远误显示

## 问题

`July-X/gitea-kanban` 仓库共 1126 条 reachable commit + 65 tag（master HEAD = `18ec0e84`）。
但应用 graph 只显示 301 条（UNCOMMITTED + 300 commits），底部一直显示「已到全部提交记录的末尾」，
滚到底也看不到 row 300 之后的 826 条更老 commit。root commit `327ac81` 永远不可见，
**用户视角**「应用仓库最早 commit 是 `882f457`（v0.7.4 commit）—— 与真实仓库 `327ac81` 不符」。

## 根因

`app/git/graph/layout_gitlens.go:862` **硬编码** `Truncated: false`：

```go
return &GraphResult{
    Nodes:     nodes,
    Edges:     edges,
    Branches:  branches,
    MaxLane:   maxCol,
    MaxColor:  16,
    Truncated: false,  // 硬编码 — LogCommits 算的截断标志丢失
}
```

`BuildGraphGitlens(commits, head, pinnedHeadShas)` 函数签名**没有 truncated 参数**——
`LogCommits` 计算的 `truncated = (len(commits) > opts.MaxCount)` 被吞掉。

`Truncated` 透传链路：
- `app/git/log.go:246-249` → 正确计算 `truncated = (len(commits) > opts.MaxCount)`
- `app/git/graph/layout_gitlens.go:862` → **硬编码 false**（断裂点）
- `app/platform/{gitea,github}/adapter.go` `graphResultToDTO` 透传到 `platform.GraphResult.Truncated`
- `app_gitgraph.go:23` `GraphResultDTO.Truncated` 透传到前端
- 前端 `TimelineNewView.vue:967-968` `allLoaded = !dto?.truncated` → truncated=false → 永远 allLoaded=true → 永远显示「已到全部」+ sentinel 哨兵 v-if=`!allLoaded` 隐藏 → 永远无法触发 loadMore

## 修复

`BuildGraphGitlens` 加 `truncated bool` 参数；两个 adapter 调它时传 `logResult.Truncated`；debug_dump_test 同步用真实 `logResult.Truncated`（不再 hardcoded `false`）；6 个测试文件调用点同步更新签名。

```go
// app/git/graph/layout_gitlens.go:696
func BuildGraphGitlens(commits []git.CommitInfo, head string, pinnedHeadShas []string, truncated bool) *GraphResult {
    // ...
    return &GraphResult{
        Truncated: truncated, // v0.8.34：透传 LogCommits 的截断标志（之前硬编码 false 丢失信号）
    }
}
```

## 对齐 vscode-gitlens

完全对齐 vscode-gitlens `hasMore` 语义（命名差异，语义完全相同）：

- vscode-gitlens: `packages/git-cli/src/providers/graph.ts` `hasMore = (limit && count >= limit)` → `renderLoadMoreRow(loadingMore)`
- 我们: `Truncated = (len(commits) > opts.MaxCount)` → 前端 `loadMoreGraph` sentinel 可见触发滚动加载

vscode-gitlens 实现的是 cursor-based paging（`getCommitsForGraphCore(limit, sha, cursor)` 增量加载），
我们前端是 window-based paging（`maxCommits += 300` 全量替换 graphDto）。
**对用户来说**：window-based paging 也能用——`maxCommits` 加到能覆盖所有 reachable commit 即可。
`July-X/gitea-kanban` 1126 commits 用 `maxCommits=1200` 一次 `loadGraph` 能看到全部。
