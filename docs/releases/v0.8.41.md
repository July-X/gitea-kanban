# v0.8.41 — GitGraph commit 详情加载动画消除 + 拆分 binding 双路加载

> 2026-08-03 · commit 详情 commit panel「加载详情中…」骨架屏消除，按 meta(O(1)) / files(subprocess) 双路异步加载

## 问题

用户截图 red-flag 反馈：

> "优化应用性能，分离渲染线程和逻辑数据加载线程，让 Git Graph 功能加载速度更快。commit log 记录都是在本地，理论上应该是不会出现 commit 详情加载 loading 动画的"

**事实核查**（基于代码扫描）：

| 路径 | 现状 | 延迟来源 |
|---|---|---|
| 打开 Git Graph 列表（loadGraph） | `await commitsGitgraphLines` 同步阻塞 UI 渲染 | Go 端 git log + GitLens GKC 算法 ~100-500ms（不可避免，没数据没法渲染） |
| **点 commit row 展开手风琴** | CommitDetailPanel watch immediate 路径：未命中 cache → `detail=null` + `loading=true` + "加载详情中…"**骨架屏**显示，等 `commitsGet` 完整返回后再填 | `r.GetCommit` (~5ms) + `r.GetCommitDiff` 2× subprocess (~60ms) ≈ 65ms |

**关键洞察**：commit row 列表已经在 `git graph lines` 返回的 nodes 里有 `subject / SHA / author / date` 基础元信息；commit panel 完全可以用这些当 placeholder **立刻显示主体**，只有 files/diff 部分等后台 IPC。

**`frontend/src/lib/wails-api-shim.ts`**：新增 `WailsApp.GetCommitMeta` / `GetCommitFiles` 接口声明 + `window.api.commits.getMeta` / `getFiles` 转接方法（对齐既有的 `forwardToWails` 模板）。

**`frontend/src/lib/ipc-client.ts`**：双路 cache 设计：

// 元信息 cache（O(1) 拉取，独立）
const metaSuccessCache = new Map<string, Promise<CommitMetaDto>>();

### CommitDetailPanel watch 重写（`CommitDetailPanel.vue`）

**P0**：watch immediate 路径**不再** `detail=null` + `loading=true`——
```ts

- P2：加 `detailSha` ref 防止 stale 覆盖

const detailSha = ref<string | null>(null);
// 新 data 到达时：if (detailSha.value !== newSha) return; // 丢弃 stale
```

**P3**：同一 watch 内**并发 fire 双路**：
```ts
// meta 路径：同步读 cache → 未命中则 fire（≈5ms O(1)）
const cachedMeta = getCachedCommitMeta(projectId, newSha);
if (cachedMeta) {
  mergeMetaIntoDetail(cachedMeta);
} else {
  void commitsGetMeta({ projectId, sha: newSha }).then((meta) => {
    if (detailSha.value !== newSha) return; // P2 stale guard
    mergeMetaIntoDetail(meta);
  });
}
// files 路径：同样 sync 读 cache → 未命中 fire（subprocess ~60ms）
// ... 同上
```

### TimelineNewView viewport prefetch（`TimelineNewView.vue`）

P1 — loadGraph 完成后**后台 fire-and-forget**预取前 20 行 commit meta：

```ts
const PREFETCH_LIMIT = 20;
async function prefetchCommitMeta(
  projectId: string | null,
  nodes: ReadonlyArray<{ sha: string }>,
): Promise<void> {
  if (!projectId) return;
  const targets = nodes.slice(0, PREFETCH_LIMIT);
  if (targets.length === 0) return;
  await Promise.allSettled(
    targets.map((node) =>
      commitsGetMeta({ projectId, sha: node.sha }).catch(() => {}),
    ),
  );
}

// loadGraph 末尾：
void prefetchCommitMeta(activeProjectId.value, nodes);
```

**为什么 20 行**：28px 行高 × 20 = 560px ≈ 1080p 屏 viewport 总高度，刚好覆盖首批可见 commit + 一些下方 buffer。

**为什么并发**：`Promise.allSettled` 兜底防单点错误；`metaSuccessCache` 命中 pending 不重发，重复调用自动 dedup。

**为什么不预取 files**：files 路径 60ms subprocess，且仅在用户点开 commit 展开手风琴时才需要——列表阶段看不到，预取浪费 IPC 资源。

**为什么不预取 deeper 老 commit**：用户初始 viewport 看不到，预取浪费；后续 loadMoreGraph 触发 loadGraph → loadGraph 结尾自动 prefetch 新一批 20 行（同一函数复用）。

## v0.8.42 patch — prefetch 扩展到 files 区（commit `0bb2f846`）

> 2026-08-03 · 用户反馈"文件变更详情还能优化吗" → A1 落地：prefetch 从 meta 扩展到 meta + files 双路

### 改动

把 `prefetchCommitMeta(projectId, nodes)` 升级为 `prefetchCommitDetails`：

```ts
// v0.8.41（仅 meta）
await Promise.allSettled(
  targets.map((node) => commitsGetMeta({ projectId, sha: node.sha }).catch(() => {})),
);

// v0.8.42（meta + files 双路并发）
await Promise.allSettled(
  targets.flatMap((node) => [
    commitsGetMeta({ projectId, sha: node.sha }).catch(() => {}),
    commitsGetFiles({ projectId, sha: node.sha }).catch(() => {}),
  ]),
);
```

每个 commit 双路并发 fire（meta O(1) ~5ms + files subprocess ~60ms），各自独立 cache，CommitDetailPanel watch 同步命中两者 → **整面板含右栏文件区零骨架屏**。

### 行为升级对照

| 操作 | v0.8.41 | v0.8.42 |
|---|---|---|
| 首 20 行 commit 点开 → meta 区 | 0ms 命中 cache | **0ms 命中 cache**（不变） |
| 首 20 行 commit 点开 → files 区 | 60ms 后到（小小骨架屏） | **0ms 命中 cache**（小骨架屏消失） |
| 第 21 行 commit 点开 | meta 5ms 到 / files 60ms 到 | 不变（仍然 5ms / 60ms，prefetch 只覆盖 viewport） |
