# v0.9.x — 切 / 同步仓库后 Git Graph 不立即刷新的 bug 修复

> 用户反馈："仓库选择新的，本地没有的仓库，同步后，Git Graph 没有立即刷新为新的仓库的记录，还是久的，需要手动在刷新操作一次"。

## Bug 根因

`selectProject` 与 `cloneRepo` 仅修改内部 ref，**没有跨视图失效信号**。下游 `TimelineNewView` 只 watch `activeProjectId`，导致：

| 场景 | 当前行为 | 期望行为 |
|---|---|---|
| 切换 project（不同 uuid） | `watch(activeProjectId)` 触发 → 调 `loadGraph()` | ✓ 实际可行但 `graphDto` 不为 null 时走 `loadingMore` 分支仅小 spinner，**旧数据残留**显示 |
| 同一 project clone 完成后本地可用 | `watch(activeProjectId)` 不触发（uuid 不变）→ **GitGraph 完全不刷新** | 应主动 retry `loadGraph` |

`StatusBar.onSyncClick` 调用 `repo.cloneRepo()` 完成 → `repo.clonedMap` 设值 → **零信号传给 TimelineNewView** → 用户回到 GitGraph 视图仍看到 addProject 时返回的 `featureDisabled` 状态，需手动点刷新。

## 修复

### 1. `frontend/src/stores/repo.ts` — 新增跨视图失效信号

```ts
const repoStoreChanged = ref(0);
function touch(): void { repoStoreChanged.value = Date.now(); }
```

`touch()` 在以下成功场景调用：

- **`cloneRepo` success（new protocol / fallback 两条路径都加）**——关键修复点：解决用户报的核心 case
- **`removeProject` 删除的是 currentProject 时**——避免 GitGraph 显示已删除项目的 stale 数据

`selectProject` / `addProject` **不**调用 `touch()`，避免与现有 `watch(activeProjectId)` 双触发跑两次 `loadGraph`（多余 IPC）。

store export `repoStoreChanged` 让视图可 watch。

### 2. `frontend/src/views/TimelineNewView.vue` — 新增 watch + 强化现有 watch

**新增**：监听 `repo.repoStoreChanged`，触发时清 `graphDto` / `featureDisabled` / `expandedSha` / `pendingFocusSha` → 调 `loadGraph()`，强制走 `firstLoad` 路径（避免走 `loadingMore` 小 spinner）。

**强化**：原有 `watch(activeProjectId)` 现在也清空上述状态，确保切 project 时旧 repo commit 数据不会残留误导用户。

### 3. 顺手清理 `frontend/src/components/CommitDetailPanel.vue`

v0.8.41 拆 binding 后 `commitsGet` 在本组件已无用，移除其 import 与 `CommitFilesDto` type 缺失（之前 typecheck 漏过，本轮顺手补）。

## 用户视角验证场景

1. 选中一个新（本地未 clone）的仓库 → `addProject` 触发 `watch(activeProjectId)` 走 firstLoad 路径 → 出现 `featureDisabled` EmptyState（clone 按钮）
2. 点 StatusBar 行末「同步」按钮 → `cloneRepo` success → repo store `touch()` → `watch(repoStoreChanged)` 触发 → 主动 `loadGraph()` 重新查后端 → 现在本地有仓库 → 正常返回 commits → GitGraph 自动渲染
3. 中途切别的 project → `watch(activeProjectId)` 触发 + 强制清空 → 旧数据不会残留误导

## 不做的事

- **不改 BranchView / PullView**：branch / pull store 各自维护 `currentProjectId` ref 与自己的列表加载，但用户**未报**这俩视图的 stale bug，留给独立 task 处理。本次只专注修复用户报的 GitGraph 场景
- **不改 `loadGraph` 内部 IPC 取消机制**：用户快速连续切 project 时老请求可能覆盖新数据，目前 50ms 时间窗内偶尔出现 → 留为后续 issue
