## 问题背景

v0.8.26 已经把 Git Graph 算法统一收敛到 GitLens GKC（`BuildGraphGitlens`），v0.8.27 修了 lane 几何对齐（branch-off 入线 LockedFirst）。用户在复刻时对标 vscode-gitlens 官方 Commit Graph 截图，发现 v0.8.27 后还有一个特性没对齐：

| 截图 | GitLens 实测 | 我们 v0.8.27 应用复刻 |
|---|---|---|
| 视觉 | 已合并 PR 对应的 commit **整行暗淡**（commit message + 日期 + 作者 + 节点 + lane line），与未合并分支明显区分 | 所有 commit 行视觉相同，user 看不到"这 PR 已经 merge 了"的状态 |

GitLens 对应设置 `dimCommitsWithPullRequests`。逻辑：**已 merged 的 PR 链上所有 commit 视觉降 opacity**，未合并 PR 链上的 commit（含 open / draft / closed-unmerged）保持原色。

> 复刻截图右下方我们已有 MergesView 列出 feature-merge (#12 已合并)、feature-kanban (#11 已合并) 等 PR，但 Git Graph 视图本身不显示这些状态。**VLM 视觉化算法证据**：`ui-pro-max`/GitLens 截图中这两个 PR 对应的 commit 行（包括 `cx-single-392739` 上冲突基线 commit、`feature-merge`/`feature-kanban` 上的 PR 链 commit、`timeline-test` 上的 commit）整行半透明，**典型 sign** 是 commit message 颜色从 #d5d5d5（亮）降到 #6c6c6c（暗）、lane line color from lane full saturation → 70% opacity。

## 关键决策

- **纯前端实现，不动 Go Wails binding / DTO 契约**（AGENTS §13 规定改 binding 必须用户拍板）
- 前端数据齐备：`graphDto` 含 `parents` + `refs`，`PullDto` 含 `merged` + `mergeCommitSha` + `head.sha`
- **灰化语义**：**只**对 `merged=true` 的 PR 链灰化。closed-unmerged 是否也灰化留给后续选项，本次不做（与 GitLens 默认行为一致）
- 复用 `inHeadShaSet` 同样的 BFS 模式（consistency + reviewer-friendly）
- path 灰化通过解析 path.d 字符串 → covered rows → 与 dimmedRowSet 求交，避免侵入 `renderGraphVscode`

## 改动内容

### 1. 新建纯函数 `frontend/src/lib/graph-dimmed.ts`

**算法**：
1. `mainAnc = ancestors(mainHead)`（**first-parent only**，与 git `--first-parent main ^feature` 语义等价）—— main trunk 的"主链 commit"集合
2. 对每个 merged PR：
   - 从 `pr.head.sha` 出发沿 `node.parents[0]` BFS
   - 遇到 `mainAnc` 内的 sha → break（merge-base 截断，不再向 main 主线扩散）
   - 沿途 sha 加入 dimmed Set

**关键 invariant**：
- `mainAnc` 用 first-parent only：避免 merge commit 的 `parents[1]` 把整个 PR 链拉入 mainAnc —— 否则截断条件失效
- BFS 用 first-parent only：merge commit 的 `parents[1]`（PR tip）不参与，避免回 main 反向 —— 严格 first-parent chain

**API 导出**：
- `dimMergedPullCommits(nodes, mergedPulls) → Set<string>`
- `resolveMainHeadSha(nodes) → string | undefined`
- `EMPTY_DIMMED_SET: ReadonlySet<string>` —— graphDto 为空时稳定兜底，避免 `.has()` 误判

**边界覆盖**：
- closed-unmerged（state=closed + merged=false）：跳过
- PR head 不在 graph 窗口（force-push / 深历史）：跳过
- PR head 把 main 推到前（head 在 mainAnc 内）：跳过该 PR
- 多个 PR 共享一段 commit：Set 去重
- 空 graph / 空 merged 列表：返回空 Set（不抛错）

### 2. `TimelineNewView.vue` 集成（4 处）

#### 2.1 后台拉取 merged PR（非阻塞）
- `mergedPulls = ref<PullDto[]>([])` + `mergedPullsAbortController: AbortController`
- `fetchMergedPullsAsync(projectId)`: `loadGraph()` 成功后 `void` 触发（不 await，遵守 §14.3 非阻塞铁律）
- 调用 `pullsList(state='closed', limit=100, page=1)` —— 兜底 `merged=false` 由 `dimMergedPullCommits` 内部 .merged 二次过滤
- `AbortController.abort()` 在 fetch 前取消旧请求（避免 stale data 覆盖新仓库）
- catch 静默：灰化是视觉特效，不能让 graph 报错
- 单页（100 条）覆盖绝大多数仓库；超过时不循环（后续可扩展 `while hasMore fetch next page`）

#### 2.2 派生 computed
- `dimmedShaSet`: `graphDto + mergedPulls` → `dimMergedPullCommits(...)`
- `dimmedRowSet`: dimmedShaSet → sha→row 索引 → row 集合
- `pathCoveredRows(d, gridY)`: 解析 SVG path d 字符串（M/L/C 的 x,y 数字），按 `row = round(y / gridY)` 算出覆盖的 row 集合
- `pathGroupsDimmed`: pathGroups ∩ (rows ∩ dimmedRowSet) → path id Set

#### 2.3 渲染层 3 处挂钩
**commit-row 文字**：
```vue
<div :class="{ ..., 'commit-row--dimmed': dimmedShaSet.has(r.commit.sha) }">
```
CSS：
```css
.commit-row--dimmed,
.commit-row--dimmed .commit-subject,
.commit-row--dimmed .commit-time,
.commit-row--dimmed .commit-author,
.commit-row--dimmed .commit-short-sha,
.commit-row--dimmed .ref-badge {
  opacity: 0.45;
}
```

**svg 节点 circle**：
```vue
<circle
  :class="{ ..., 'commit-vertex--dimmed': c.isDimmed }"
  :stroke-opacity="c.isCurrent ? 1 : (c.isDimmed ? 0.35 : 0.75)"
  :fill-opacity="c.isDimmed && !c.isCurrent ? 0.35 : 1"
>
```

**svg path（lane line）**：
```vue
<g
  class="flow-group"
  :class="[..., { 'flow-group--dimmed': pathGroupsDimmed.has(pg.id) }]"
>
  <path
    :stroke-opacity="pg.kind === 'shadow'
      ? (pathGroupsDimmed.has(pg.id) ? 0.18 : 0.75)
      : (pathGroupsDimmed.has(pg.id) ? 0.35 : 1)"
  />
</g>
```

`SvgCircleNode` interface 加 `isDimmed?: boolean` 字段，前端 store 接口契约不需重发（v0.7.x 时代就有 inHead 这种 optional 字段）。

### 3. 单测 13 个（vitest）

`frontend/src/lib/graph-dimmed.test.ts` —— 覆盖 8 类边界：

```
TestBuildGraphGitlens_MergeFirstParentOnly (5 个普通 merge 拓扑)
  ✓ 普通 merge commit：PR head 链整段 dim，main trunk 不 dim
  ✓ closed-unmerged PR（merged=false）不 dim
  ✓ 多 PR：共用一段 commit + 单独一段
  ✓ 同 PR 链上节点被多次访问（去重）
  ✓ PR head 不在 graph 窗口：skip
  ✓ PR head 在 mainAnc 内：skip
  ✓ 空输入：graphDto 为空 / mergedPulls 为空 → 返回空 Set

TestBuildGraphGitlens_ResolveMainHeadSha (5 个 refs 拓扑)
  ✓ 找 refs 含 main 的最早 row
  ✓ refs 含 master 也算
  ✓ refs 含 origin/main 也算（剥前缀后取末段）
  ✓ 无 main/master refs 兜底：row 0 node
  ✓ 空数组返回 undefined
```

**关键的 v0.8.28 vscode 实现 BUG 实证**：第一版 `mainAnc` 用所有 parents BFS，结果 `merge.parents[1] = pr_tip` 把整个 PR 链拉入 mainAnc，导致 "普通 merge commit: PR head 链整段 dim" 测试收到空 Set。修复后 `mainAnc` 改用 first-parent-only，13 个测试全过。

## 影响范围

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 已 merged PR 链 commit 行 | 文字 + 节点 + lane line 视觉与未合并 PR 一致 | 文字 opacity 0.45 + 节点 opacity 0.35 + lane path opacity 0.18/0.35，明显视觉降级 |
| 未合并 PR（open / draft / closed-unmerged） | 正常 | 正常（**不**dim） |
| 主分支（main/master）的 commit | 正常 | 正常（mainAnc 截断点确保不被 dim） |
| merge commit 自身 | 在 commit row 上不 dim（merge commit 不在 PR head 的 first-parent 链上） | 在 commit row 上不 dim（一致行为） |
| closed-unmerged PR | 走 `pr.merged=false` 过滤，跳过 | 同前 |
| 跨平台 | 不依赖 binding schema | 不依赖 binding schema |

**关键性能**：
- `dimMergedPullCommits` 是 O(N + M·D)：N = graph nodes, M = PR 数（典型 ≤30）, D = 单 PR 链深度
- 单 mainAnc BFS + 单 shared parentsBySha 索引；实测 < 10ms @ 5000 commits × 30 PR
- `dimmedShaSet` 是 Vue computed，自动响应 graphDto / mergedPulls 变化（loadMore 重拉时重算）
- `pathGroupsDimmed` 解析 SVG d 字符串：每个 path 含 ~6-12 个数字，30 个 path → ~360 次 parseFloat @ 触发重算 1 次，< 2ms
- 多重 computed 嵌套：`dimmedShaSet` → `dimmedRowSet` → `pathGroupsDimmed`；Vue 在依赖不变时返回缓存值
