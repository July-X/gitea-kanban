## 问题背景

`app/platform/github/adapter.go:EnsureForkParentRemote` 在 GitHub 仓库
`CloneRepo` 完成（adapter.go:297）和 `PullRepoByProjectId` 每次刷新
（app_sync.go:99）自动触发，行为是：

1. 调 `parentCloneURL` 通过 GitHub API 查 fork parent 的 clone URL
2. `EnsureRemote(localPath, "org", parentCloneURL)` 加 `org` remote
3. `FetchWithFilter` 拉 `org` remote 的所有 `refs/heads/*`

### 现象

用户 fork `esengine/DeepSeek-Reasonix`（活跃开源项目，23 个
dependabot PR branch）后，应用数据目录
`C:\Users\zxx\.gitea-kanban\workspace\repos\July-X\July-X__DeepSeek-Reasonix`
比源码仓库 `D:\2026\github\DeepSeek-Reasonix` 多 50 个 branch（23 个
`org/dependabot/*` + 5 个 `org/codex/*` + 5 个 `org/feature/*` +
多个 `org/fix/*` + 几个 `org/{star-history,v1,...}` 等）。

应用 git graph 把上游 dependabot PR tip commit（如 50e77137）也画出来，
maxLane 从 14 涨到 15，"b2139fe 视觉在 lane 2、颜色 lane 1" 那种矛盾
现象更严重。vscode-gitlens 搜不到 50e77137（它只显示当前 branch graph，
不遍历 50 个 branch）→ 用户误以为应用"凭空捏造"了 commit。

### 根因

注释（`adapter.go:303-305`）明确说设计意图是：

> "VSCode Git Graph 会显示工作区里已有的 upstream 分支和 tag。应用自己的轻量克隆如果只拉 origin，就会漏掉 fork parent 上的**发布 tag** / **org 分支**"

但 `FetchWithFilter` 用 `+refs/heads/*:refs/remotes/org/*` 拉**所有 branch**——
把上游 dependabot PR（npm/github_actions/go_modules/...）全部拉进
用户的 fork 仓库本地引用。**实际行为与设计意图脱节**：
- 注释意图：拉 fork parent 的**发布 tag + 主分支**（装饰信息）
- 实际行为：拉**所有 refs/heads/* 含 23 个 dependabot PR branch**

`parentCloneURL` 的返回值在整个项目里**没有任何消费方**（grep frontend/src 0 命中）——这个 fork 关系对前端 UI 是 dead data。

## 改动内容

### 1. 删除两处调用

- `app/platform/github/adapter.go:297 CloneRepo` 完成后：删 `EnsureForkParentRemote` 调用
- `app_sync.go:99 PullRepoByProjectId` 每次刷新：删 `EnsureForkParentRemote` 调用

### 2. 删除 `EnsureForkParentRemote` 函数体

- 行为错误的函数整体移除
- 孤儿变量 `apiHostURL` 清理（CloneRepo 里的局部变量）
- 函数注释里"显示 fork parent 发布 tag / org 分支"设计意图被新原则取代：
  **"只同步当前账号仓库基本信息，不关心 fork 源信息"**

### 3. 保留 `parentCloneURL` 函数

- 这是无副作用的纯 GitHub API 调用
- 当前**没有消费方**（grep 全仓 0 命中）
- 保留供未来"显示 fork 关系"UI 使用

### 4. 行为对比

| 场景 | 改前 | 改后 |
|---|---|---|
| 用户连接 GitHub 账号 | 走 `/user/repos`（已经是当前账号视图） | 不变 |
| 用户 clone fork 仓库 | CloneRepo + EnsureForkParentRemote 拉 23 个 PR | 只 clone，不拉 fork parent |
| 用户每次点"刷新" | PullRepo + EnsureForkParentRemote 再次拉 | 只 fetch origin |
| git graph 显示 | main + 23 个上游 PR commit | 只 main + 自己的 work-in-progress |
| maxLane | 14 + dependabot PR 数量 | 14（稳定） |
| "forked from" 装饰信息 | 注释里描述但实际未消费 | 不变（之前也没消费） |
