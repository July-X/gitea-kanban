> 发布日期：2026-07-30
> commit：（待 push 后回填）
> tag：（待打）
> release：https://github.com/July-X/gitea-kanban/releases/tag/v0.8.27

## 问题背景

Windows 用户切到 GitHub 数据源后点刷新（`commits.gitgraphPull` → `FetchRepo` → `FetchWithFilter` → `git fetch --filter=blob:none`），报：

```
git: 'remote-https' is not a git command. See 'git --help'.
fatal: remote helper 'https' aborted session
```

且同次调用还同时撞第二堵墙——`!gh auth git-credential` 走 credential helper 需要 `sh.exe` 解析 `!` 前缀，但内嵌 git 旁没 sh。

## 根因

**内嵌 git 二进制布局缺陷**：

- 仓库内嵌的 `app/gitbinary/binaries/git/gk-git-2.55.0-windows-amd64.exe`（4.38 MB）是从 MinGit-2.55.0-windows.1 提取的 `cmd/git.exe` 单文件
- 单文件布局**不带** `git-remote-https.exe` / `git-remote-http.exe` / `git-http-fetch.exe` / `git-http-push.exe` 等 remote helper
- 也不带 `libcurl-4.dll` / `libssl-3-x64.dll` / `libcrypto-3-x64.dll` / `libcurl-openssl-4.dll` 等 DLL 依赖
- `git fetch <https remote>` 时 git 主进程 fork `git-remote-https.exe`，查找顺序：
  1. `<argv0>/../mingw64/libexec/git-core/`（单文件布局不存在）
  2. `GIT_EXEC_PATH` env（未设置）
  3. `PATH`（用户没装系统 git 时也不存在）
  → 报错 `remote-https is not a git command`

**fetch 鉴权链路依赖 gh**：

- 旧 `fetchRemoteWithFilter` 用 `-c credential.helper=!gh auth git-credential` 走 gh credential helper
- Windows 上 `!` 前缀需要 `sh.exe` 解析（git 内置行为），MinGit 单文件布局没带
- 且 gh 不是内嵌，Windows 用户大概率没装
- 即使修好 remote helper，credential helper 还要走另一条链路

## 改动内容

### 1. 内嵌 Windows git remote helper + DLL 依赖

**新增** `app/gitbinary/binaries/git/windows-helper/` 子目录，22 个运行时文件（约 22 MB）：

```
git-remote-https.exe       git-remote-http.exe       git-http-fetch.exe       git-http-push.exe
libcurl-4.dll              libcurl-openssl-4.dll
libssl-3-x64.dll           libcrypto-3-x64.dll
libbrotlidec.dll           libbrotlienc.dll          libbrotlicommon.dll
libnghttp2-14.dll          libidn2-0.dll             libpsl-5.dll
libssh2-1.dll              libunistring-5.dll
libzstd.dll                zlib1.dll                 libpcre2-8-0.dll
libiconv-2.dll             libintl-8.dll             libexpat-1.dll
```

来源：MinGit-2.55.0-64-bit.zip `mingw64/bin/`。依赖链通过 PE 静态导入表 + `LoadLibrary` 动态依赖实测确认（用 `app/gitbinary/runner_e2e_test.go` 验证）。

子目录 `.gitignore` 白名单 `!*.exe` / `!*.dll`（根 `.gitignore` 全局黑名单 `*.dll` 需要在子目录反向白名单）。

### 2. `embed_windows.go` + Init 释放 helper

**`app/gitbinary/embed_windows.go`**：

- 加 `//go:embed binaries/git/windows-helper` 嵌入到 `embed.FS`
- 新增 `embeddedHelperFS()`（用 `fs.Sub` 限定到子目录）/ `embeddedHelperAvailable()` 函数
- 注释说明 helper 依赖链 + Init 释放流程

**`app/gitbinary/helper_darwin.go`** / **`app/gitbinary/helper_other.go`**（**新增**）：

- darwin / linux 平台 stub：返 `nil`
- 当前仅 Windows 嵌入 helper（macOS 沙箱 git 通常是 homebrew Cellar 完整布局，不需要嵌入）

**`app/gitbinary/runner.go`**：

- 新增 `releaseHelpers(target, toolsDir, logger) bool` 函数：`fs.WalkDir` 遍历嵌入 FS，逐个 `os.WriteFile` 到 `${dataDir}/tools/git/`
- Init 流程增加 helper 释放步骤（chmod 同主二进制 0755 跳过——windows 不需执行位）
- 失败仅 WARN 不阻断启动：本地命令（log / rev-parse）仍可用
- Windows 平台 Init 末尾额外跑 `git ls-remote https://github.com/git/git.git HEAD` smoke test 验证 helper 链通（失败仅 WARN，离线环境不误伤）

### 3. `GitEnvFor` 注入 `GIT_EXEC_PATH`

**`app/gitbinary/runner.go`**：

- 新增 `GitEnvFor(binPath string, extraEnv map[string]string) []string` 公开函数
- 智能判定：当 `filepath.Dir(binPath) == filepath.Dir(DefaultBinaryPath())`（即内嵌二进制路径）时，注入 `GIT_EXEC_PATH=<binDir>`；系统 git / 用户自定义路径不注入（避免破坏相对 exec-path 解析）
- extraEnv 合并时去重（同 key 后者覆盖）
- `RunGitWithEnv` 改用 `GitEnvFor` 构造 cmd.Env

**测试**：`app/gitbinary/runner_e2e_test.go:TestEndToEnd_RunGitWithEnv_HelperFound` 验证 helper 链通（沙箱离线环境不强求联通 GitHub，只断言错误信息不含 "remote-https is not a git command"）。

### 4. fetch 鉴权从 gh credential helper 改为 env-based extraHeader

**`app/git/native.go:fetchRemoteWithFilter`**：

- 删 `args = []string{"-c", "credential.helper=!gh auth git-credential", "fetch", ...}`
- token 非空时 envVars 注入：
  - `GIT_CONFIG_COUNT=1`
  - `GIT_CONFIG_KEY_0=http.https://github.com.extraHeader`（限定到 github.com 域，避免 token 泄露给其它 remote）
  - `GIT_CONFIG_VALUE_0=Authorization: Bearer <token>`（经 env 传入，不进命令行 / stderr 输出，符合 §8.1 鉴权铁律）
- token 为空时不注入 env config（公开仓库 fetch 无需鉴权）

**`app/git/native.go:FetchWithFilter`**：

- 删 `gitbinary.ResolveGhPath` 检查 + `ipc.NewGhNotInstalled` 错误返回（fetch 不再依赖 gh）

**`app/git/native.go:fetchRemoteWithFilter`** 错误信息修：

- 删 `fmt.Errorf("git fetch %s 失败: %w\n输出: %s", remote, err, string(output))` 中额外的「输出: %s」——`RunGitWithEnv` 的 err 已包含输出详情，重复拼接让用户看到两遍「输出: ...」

### 5. 跨平台 stub 文件

| 文件 | build tag | 作用 |
|---|---|---|
| `app/gitbinary/embed_windows.go` | windows | 嵌入主二进制 + helper + DLL |
| `app/gitbinary/embed_darwin.go` | darwin | 嵌入主二进制（不含 helper，macOS homebrew git 完整布局自带 helper） |
| `app/gitbinary/embed_other.go` | !darwin && !windows | linux/freebsd stub |
| `app/gitbinary/helper_darwin.go`（**新增**） | darwin | helper FS stub 返 nil |

代码路径跨平台通用：若未来 macOS 用户撞同类 bug（sandbox git 是 universal 单文件），可直接扩展 `helper_darwin.go` 嵌入 homebrew helper 链，**不需改 runner.go**。

### 6. 测试覆盖

**新增 `app/git/native_test.go`**（7 测试）：

- `TestFetchRemoteWithFilter_EnvNoToken` — token 为空时不注入 env config

- `TestGitEnvFor_InjectsExecPathForEmbedded` — 内嵌路径注入 `GIT_EXEC_PATH`
- `TestGitEnvFor_NoExecPathForSystemGit` — 系统 git 不注入
- `TestGitEnvFor_ExtraEnvOverrides` — extraEnv 同 key 覆盖基础 env

**新增 `app/gitbinary/runner_e2e_test.go`**（2 测试）：

- `TestEndToEnd_InitReleasesHelpers` — Init 释放 11 个关键 helper + DLL 到 `tools/git/`
- `TestEndToEnd_RunGitWithEnv_HelperFound` — 端到端断言错误信息不含 `remote-https is not a git command`（helper 链通）

**测试统计**：

- v0.8.26 之前：60+ 测试 / 11 包

## 回归风险

| 风险 | 缓解 |
|---|---|
| DLL 依赖链漏 DLL | `TestEndToEnd_InitReleasesHelpers` 列具体文件清单；Init 末尾 `ls-remote` smoke test 端到端验证 |
| 内嵌体积膨胀 | 单 helper bundle 22 MB（acceptable，已对齐 macOS 内嵌 git 3.85 MB + Linux 用户的 22 MB 增量换零依赖） |
| extraHeader 跨 host 泄露 | 限定 `http.https://github.com.extraHeader` 不带全 host 通配 |
| token 进命令行 | env 注入符合 §8.1 鉴权铁律（不进 args / stderr / 日志） |
| 系统 git 路径注入 GIT_EXEC_PATH 破坏相对解析 | `GitEnvFor` 只对内嵌二进制路径触发 |
| macOS 沙箱 git 撞同类 bug | `helper_darwin.go` stub 已就位，未来直接扩展 |
| 离线环境 Init 失败 | Init 末尾 `ls-remote` smoke test 失败仅 WARN，不阻断启动 |
