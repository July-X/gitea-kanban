## 问题背景

v0.8.25 ~ v0.8.26 系列已把 Git Graph 算法统一收敛到 GitLens GKC（`BuildGraphGitlens`，`5caa347` / `aa3b599`）。用户对标 GitLens 官方 Commit Graph 截图（vscode-gitlens/packages/plus/commit-graph）复测我们的应用复刻，发现 branch-off 入线（feature branch 顶端从主干分叉的转场斜线）的视觉走向与 GitLens 实测不一致：

| 截图 | 我们应用的复刻 | GitLens 原版 |
|---|---|---|
| 视图 | 多 commit 上方斜线呈「lane 0/2 一直竖直到 commit 行附近才斜切」 | 「branch 在 child 端立即斜切 + 之后竖直」 |
| 几何 | `LockedFirst=false`（转场在下端 parent 端） | `LockedFirst=true`（转场在上端 child 端） |

**症状**：浏览 wip draft placeholder、Merge PR #…、origin/<timeline-test> 等"在 main lane 右侧新开 lane"的几何时，lane 0/2 那条线的"凭空向下冒出来"，看起来很别扭；而 GitLens 是从 commit 圆点附近斜切到新 lane，更自然。

## 根因

`app/git/graph/layout_gitlens.go` 的 `segmentToLines` 函数里，3 处 stitch 入线的 `LockedFirst` 计算不一致：

| 路径 | 行号 | 原 `LockedFirst` | 几何 | 期望 |
|---|---|---|---|---|
| merge stitch | 592 | `mergeCol < firstCol` (动态) | parent 上端 / child 下端 / X1<X2 main 在左 | `true` ✓ |
| branch-off | 612 | **`false` 写死** | parent 上端 / child 下端 / X1<X2 main 在左 | **`true`** |
| fork stitch | 674 | `false` 写死 | **child 上端** / parent 下端 / X1>X2 | `false` ✓ |
| segment 内线（lane 压缩造成跨 lane） | 644 | `c1 != c2` 动态 | child 在下端 | `true` ✓ |
| merge incoming line（合入既有 lane） | 884 | `true` 写死 | merge dot 在上端 | `true` ✓ |

merge stitch、merge incoming、lane 压缩内线、fork stitch 这 4 处的 LockedFirst 都与对应几何匹配（前 3 个是"child 在下端"类，转场在上端 child 端；fork stitch 是"child 在上端"类，转场在下端 parent 端）。**唯一 bug 在 v0.8.25.3 引入的 `branchSha` 写死 `false`**——它的几何与 merge stitch 完全等价（parent 在上端 / child 在下端 / 跨 lane），但 LockedFirst 用了相反的值，是 v0.8.25.3 移植 GitLens 时凭印象写的，与实测对不上。

## 改动内容

### 1. layout_gitlens.go branchSha 入线 LockedFirst 修复

```go
// 修复前（v0.8.25.3 ~ v0.8.26.x）
lines = append(lines, GraphBranchLine{
    X1: branchCol, Y1: branchRow,
    X2: firstCol, Y2: firstRow,
    LockedFirst: false,  // ← 与 merge stitch 几何等价但语义相反
    IsCommitted: true,
})

// 修复后（v0.8.27）
lockedFirst := branchCol < firstCol  // 与 line 588 merge stitch 同向
lines = append(lines, GraphBranchLine{
    X1: branchCol, Y1: branchRow,
    X2: firstCol, Y2: firstRow,
    LockedFirst: lockedFirst,
    IsCommitted: true,
})
```

### 2. 同步审视其余 4 处 LockedFirst

通过几何一致性盘点确认：merge stitch、merge incoming、lane 压缩内线、fork stitch 这 4 处的 `LockedFirst` 值都与各自的几何方向对齐，**只有 branch-off 是错的**。修复策略最小：单文件 +8/-4 改动，无 schema 变化、不需前端重新构建、不破 Wails binding。

## 影响范围

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 单行 trans-lane branch-off（abs row diff = 1 gridY） | angular 折线 midX=x1/midY=y1+0.38*gridY | angular 折线 midX=x2/midY=y2-0.38*gridY |
| 多行 trans-lane branch-off（abs row diff > 1.5*gridY） | pushSplit「先竖后斜」（parent 端转场） | pushSplit「先斜后竖」（child 端转场） |

**关键用例**：
- `TestBuildGraphGitlens_RealWorldScenario` 的 branch 1 = head00：`line (0,0)→(1,11)` LockedFirst 由 false 变 true → 11 行长线从「lane 0 竖直到 row 10→11 才斜切」变成「row 0 立即斜到 lane 1 row 1，再竖直到 row 11」，与 GitLens「branch 在 child 端出现」的形态完全对齐。
- 用户截图里行 1/10/21/22 commit 上方斜线：修复后视觉上从「上方凭空冒出」变成「child 圆点附近斜切」。
